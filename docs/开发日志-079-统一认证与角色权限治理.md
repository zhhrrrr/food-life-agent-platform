# 开发日志-079-统一认证与角色权限治理

## 本次目标

在保留黑马点评 Redis Token 登录方案的基础上，补齐非 Agent 阶段需要的轻量角色权限模型。

这一步解决的问题是：不能让所有写操作都只依赖普通用户登录态。库存调整、退款确认这类接口应该有运营身份边界。

## 核心判断

当前项目不适合一上来做完整 RBAC 权限系统，因为业务主线仍在交易、拼团、秒杀、微服务治理上。更合理的是先做轻量可落地版本：

- 用户登录还是 Redis Token。
- Token 中增加角色字段。
- auth-starter 统一解析角色。
- 配置中声明哪些路径需要哪些角色。
- 本地环境允许用 `local-user-roles` 指定测试用户角色。

后续如果需要真正公司级权限系统，可以再迁移到：

- 用户-角色表
- 角色-权限表
- 菜单/按钮权限
- 商家员工表
- 运营后台账号体系

## 本次新增能力

### 1. LoginUserDTO 增加角色

文件：

- `food-auth-starter/src/main/java/com/foodlife/auth/model/LoginUserDTO.java`

新增字段：

- `role`

作用：

- 当前线程内可以通过 `UserHolder.getUser().getRole()` 判断用户角色。
- 后续 Controller、应用服务、审计日志都可以拿到用户身份类型。

### 2. 登录 Token 增加默认角色

文件：

- `food-user-service/food-user-trigger/src/main/java/com/foodlife/user/trigger/http/UserAuthController.java`

登录成功写 Redis Hash 时新增：

- `role=USER`

说明：

- 普通手机号登录默认都是 C 端用户。
- 不改变原有黑马点评登录流程。

### 3. RefreshTokenInterceptor 解析角色

文件：

- `food-auth-starter/src/main/java/com/foodlife/auth/interceptor/RefreshTokenInterceptor.java`

改造点：

- 从 Redis Token Hash 中读取 `role`
- 如果配置了本地用户角色覆盖，则优先使用覆盖角色
- 如果没有角色，默认使用 `USER`

本地覆盖的作用：

- 不需要单独开发运营后台登录。
- 可以用测试用户 ID 模拟 `ADMIN`、`OPERATOR`、`MERCHANT`。
- 适合当前课程项目和面试项目阶段。

### 4. AuthProperties 增加 role-access 配置

文件：

- `food-auth-starter/src/main/java/com/foodlife/auth/properties/AuthProperties.java`

新增配置结构：

- `food.auth.role-access.enabled`
- `food.auth.role-access.default-role`
- `food.auth.role-access.local-user-roles`
- `food.auth.role-access.paths[].pattern`
- `food.auth.role-access.paths[].roles`

含义：

- `paths[].pattern`：需要角色控制的路径
- `paths[].roles`：允许访问该路径的角色
- `local-user-roles`：本地测试环境给指定用户覆盖角色

### 5. 新增 RoleAccessInterceptor

文件：

- `food-auth-starter/src/main/java/com/foodlife/auth/interceptor/RoleAccessInterceptor.java`

执行顺序：

1. `RefreshTokenInterceptor`：解析 token，刷新 TTL，放入 `UserHolder`
2. `InternalCallInterceptor`：保护内部接口
3. `LoginInterceptor`：校验是否登录
4. `RoleAccessInterceptor`：校验角色是否允许访问当前路径

处理结果：

- 未登录 -> `401`
- 角色不允许 -> `403`
- 角色允许 -> 放行

### 6. trade-service 配置运营权限

文件：

- `food-trade-service/food-trade-app/src/main/resources/application-local.yml`
- `deploy/nacos/configs/food-trade-service.yaml`

新增角色保护：

- `/api/trade/operations/**`
  - `ADMIN`
  - `OPERATOR`
- `/api/trade/orders/*/refund/confirm`
  - `ADMIN`
  - `OPERATOR`

本地测试角色：

- userId = `1` -> `ADMIN`

说明：

- 运营库存调整不能再由任意登录用户调用。
- 退款确认不再是普通用户权限。
- 后续如果有商家核销后台，可以继续增加 `/api/trade/merchant/** -> MERCHANT/ADMIN`。

## 前端调整

文件：

- `food-life-agent-web/src/api/trade.ts`

调整：

## 当前权限链路

以“运营库存调整”为例：

1. 请求进入 Gateway
2. Gateway 校验 Redis Token
3. Gateway 透传 authorization
4. trade-service `RefreshTokenInterceptor` 解析 token
5. 本地配置把 userId=1 覆盖成 `ADMIN`
6. `LoginInterceptor` 校验登录态
7. `RoleAccessInterceptor` 命中 `/api/trade/operations/**`
8. 校验 `ADMIN` 是否在允许角色列表
9. 通过后进入 `OperationStockAdjustmentController`
10. 执行业务库存调整链路
