# 开发日志 045：评价管理与摘要接口

## 一、本次目标

继续完善不涉及 Agent 的业务部分。

上一轮已经完成“核销后创建评价”，本轮补齐评价域的三个能力：

1. 用户隐藏自己的评价。
2. 隐藏评价时回滚店铺评论数和评分。
3. 按套餐查询评价列表。
4. 查询店铺评价摘要，供店铺详情页展示最新评价。

## 二、为什么要加评分快照

店铺表当前用：

```text
shop.comments
shop.score
```

保存聚合数据，其中 `score` 是十分制整数，例如 `46` 表示 `4.6` 分。

如果隐藏评价时只用下面方式反推：

```text
(当前 score * 当前 comments - 评价分 * 10) / (当前 comments - 1)
```

会遇到整数取整误差。

所以本次新增：

```text
shop_review.shop_comments_before
shop_review.shop_score_before
```

创建评价前先记录店铺原始聚合值；后续隐藏该评价时，优先使用快照恢复，避免评分被反复增删后越算越偏。

## 三、业务流程

### 1. 隐藏评价

```text
用户携带 token 请求 business-service
  -> business-service 从 UserHolder 获取 userId
  -> 按 reviewId + userId 查询自己的正常评价
  -> 将 review_status 从 1 改为 0
  -> 如果评价里有店铺聚合快照，直接恢复 shop.comments 和 shop.score
  -> 如果没有历史快照，走旧的反算兜底逻辑
  -> 返回删除结果
```

这里是业务隐藏，不是物理删除。

同一订单仍保持“一笔订单生命周期只允许一条评价”的约束，避免用户删除后反复刷评价。

### 2. 套餐评价列表

```text
GET /api/package/{packageId}/reviews
```

该接口只查询 `review_status=1` 的有效评价，支持游标分页。

### 3. 店铺评价摘要

```text
GET /api/shop/{shopId}/review-summary
```

返回：

- 店铺 ID
- 店铺评论数
- 店铺评分
- 最新 3 条有效评价

## 四、接口

### 1. 隐藏我的评价

```http
DELETE /api/reviews/{reviewId}
authorization: {token}
```

成功响应：

```json
{
  "code": "0000",
  "message": "success",
  "data": {
    "reviewId": 2,
    "userId": 44,
    "shopId": 1,
    "packageId": 1,
    "orderId": 63,
    "reviewStatus": 0,
    "deleted": true
  }
}
```

重复隐藏响应：

```json
{
  "code": "400",
  "message": "review not found",
  "data": null
}
```

### 2. 套餐评价列表

```http
GET /api/package/1/reviews?pageSize=5
```

### 3. 店铺评价摘要

```http
GET /api/shop/1/review-summary
```
