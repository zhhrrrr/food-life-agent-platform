# 开发日志 014：修正普通购买责任链用法

## 一、本次问题

之前普通购买下单校验链拆成了：

```text
COMMAND 阶段链：只有 OrderCommandCheckHandler 一个节点
SNAPSHOT 阶段链：只有 PackageTradeCheckHandler 一个节点
```

这种写法虽然使用了 `LinkArmory` 和 `BusinessLinkedList`，但责任链价值不明显。

xfg 拼团项目里的典型用法是：

```text
一条业务链中显式声明多个节点，
节点按顺序执行，
节点之间通过 dynamicContext 传递中间数据。
```

例如拼团锁单链：

```text
ActivityUsabilityRuleFilter
UserTakeLimitRuleFilter
TeamStockOccupyRuleFilter
```

因此本次修正普通购买责任链。

## 二、调整后的普通购买校验链

文件：

```text
food-trade-domain/src/main/java/com/foodlife/trade/domain/order/check/OrderCreateCheckChain.java
```

现在只有一条链：

```text
普通购买下单规则过滤链
```

链路节点顺序：

```text
1. OrderCommandCheckHandler
2. PackageSnapshotLoadHandler
3. PackageStatusCheckHandler
4. PackageStockCheckHandler
```

组装方式：

```text
LinkArmory
BusinessLinkedList
```

## 三、节点职责

### OrderCommandCheckHandler

职责：

```text
校验用户是否登录
校验 packageId 是否为空
校验 quantity 是否合法
```

### PackageSnapshotLoadHandler

职责：

```text
调用 business-service 查询套餐交易快照
将快照写入 OrderCreateContext
```

这一步参考了 xfg 拼团链路里：

```text
节点查询业务数据并写入 dynamicContext
```

### PackageStatusCheckHandler

职责：

```text
校验套餐是否存在
校验套餐是否上架
```

### PackageStockCheckHandler

职责：

```text
校验套餐库存是否足够
```

## 四、OrderDomainService 调整

文件：

```text
food-trade-domain/src/main/java/com/foodlife/trade/domain/order/service/OrderDomainService.java
```

原来领域服务中直接调用：

```text
businessPackagePort.queryTradeSnapshot
```

现在改为：

```text
orderCreateCheckChain.checkNormalOrder(context)
PackageTradeSnapshot snapshot = context.getPackageSnapshot()
```

也就是说：

```text
套餐快照加载和下单前规则校验统一放入普通购买责任链。
```

领域服务仍然显式编排普通购买业务流程，但下单前过滤规则交给责任链。

## 五、删除内容

删除：

```text
OrderCreateCheckStage
PackageTradeCheckHandler
```

原因：

```text
不再拆 COMMAND/SNAPSHOT 两条单节点链。
PackageTradeCheckHandler 被拆成 PackageStatusCheckHandler 和 PackageStockCheckHandler。
```

## 六、当前普通购买流程

```text
1. 构建 OrderCreateContext
2. 执行普通购买下单规则过滤链
3. 从 context 获取套餐快照
4. 执行价格策略
5. 创建订单主表
6. 保存订单主表
7. 创建订单明细
8. 保存订单明细
9. 返回订单结果
```

通过。

## 八、本次结论

这次修正后，普通购买的责任链用法更接近 xfg 拼团项目：

```text
一个明确的业务链
多个规则节点
LinkArmory 显式组装顺序
dynamicContext 传递中间数据
```

后续拼团和秒杀也应该按这个方式建自己的业务链，而不是拆成多个单节点小链。
