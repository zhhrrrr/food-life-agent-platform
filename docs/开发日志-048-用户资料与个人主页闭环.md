# 开发日志-048-用户资料与个人主页闭环

## 1. 本次目标

本次继续做非 Agent 业务能力，在 `food-user-service` 内新增用户资料和个人主页能力。

它承接上一阶段的关注关系：

```text
用户基础资料
关注数
粉丝数
当前登录用户是否关注目标用户
```

这块后续可以给评价作者页、收藏主页、Feed、推荐和生活助手入口复用。

## 2. 新增接口

```http
GET /api/user/profile/me
PUT /api/user/profile
GET /api/user/homepage/{userId}
```

说明：

```text
当前项目的 /api/user/** 默认需要登录。
个人主页第一版也要求登录访问，这样可以返回 following 字段。
后续如果要做公开主页，可以在 auth exclude-paths 里放开 homepage，再做可选登录解析。
```

## 3. 业务规则

```text
1. userId 只能从 UserHolder 获取。
2. 修改资料时 nickName 必填。
3. nickName 长度 2-32。
4. icon 最大 255。
5. city 最大 64。
6. bio 最大 200。
7. foodPreference 最大 200。
8. 查询个人主页时隐藏 phone。
9. 查询我的资料时返回 phone。
10. 修改昵称头像后同步当前 Redis Token Hash，避免 /api/user/me 继续显示旧昵称头像。
```

## 6. 与关注关系的聚合

个人主页返回：

```text
followingCount
fansCount
following
```

其中：

```text
followingCount 来自 user_follow 中当前用户关注中的数量。
fansCount 来自 user_follow 中关注当前用户的数量。
following 表示当前登录用户是否关注目标用户。
```

## 7. 本次验证项

已验证：

```text
1. user-service 编译通过。
2. 本地 food_user_db 能创建 user_profile 表。
3. 登录用户能查询自己的资料。
4. 登录用户能更新昵称、头像、城市、简介、美食偏好。
5. 更新后 /api/user/me 能读到新的昵称头像。
6. 查询目标用户个人主页不返回 phone。
7. 目标用户主页能返回关注数、粉丝数和 following。
8. 缺少 nickName 时返回 nickName required。
9. 未登录访问返回 401 用户未登录。
10. 查询不存在用户主页返回 user not found。
```
