# 开发日志-058-微服务网关统一入口

## 本次目标

把项目从“前端/脚本分别访问三个业务服务”推进到“统一访问网关，再由网关按服务名路由到后端微服务”。

本次只做网关入口和本地联调闭环，不把业务鉴权、订单规则、库存扣减等业务逻辑放进网关。

## 新增微服务

### food-gateway-service

定位：微服务流量入口。

负责：

- 统一接收前端 HTTP 请求，默认端口 `8080`
- 通过 Spring Cloud Gateway 路由到用户、业务、交易三个服务
- 通过 Nacos 注册到注册中心
- 从 Nacos 配置中心读取网关路由配置
- 处理跨域配置，便于前端联调
- 生成或透传 `X-Trace-Id`，方便后续排查跨服务链路

不负责：

- 不做订单、店铺、用户等业务规则
- 不直接访问 MySQL 或 Redis
- 不替代下游服务里的黑马点评登录拦截

## 路由规则

| 网关路径 | 目标服务 | 说明 |
| --- | --- | --- |
| `/api/user/**` | `food-user-service` | 登录、短信验证码、当前用户、资料、关注 |
| `/api/shop-category/**` | `food-business-service` | 店铺分类 |
| `/api/shop/**` | `food-business-service` | 店铺详情、店铺列表、评价列表 |
| `/api/package/**` | `food-business-service` | 套餐详情、套餐列表、交易快照、库存变更 |
| `/api/shop-homepage/**` | `food-business-service` | 店铺主页聚合 |
| `/api/reviews/**` | `food-business-service` | 评价发布、我的评价、删除评价 |
| `/api/favorites/shops/**` | `food-business-service` | 店铺收藏 |
| `/api/trade/**` | `food-trade-service` | 普通购买、拼团、秒杀、支付、退款、核销、优惠券 |

## Nacos 接入方式

新增配置文件：

- `deploy/nacos/configs/food-gateway-service.yaml`

新增客户端配置：

- `food-gateway-service/src/main/resources/bootstrap.yml`
- `food-gateway-service/src/main/resources/application.yml`

本地默认：

- 不开 Nacos 时，Gateway 使用 `SimpleDiscoveryClient` 指向本机 `8101/8201/8301`
- 开 Nacos 时，Gateway 注册为 `food-gateway-service`，并通过 `lb://服务名` 发现下游服务

## 脚本改动

- `scripts/start-local-services.ps1` 增加 `-IncludeGateway`
- `scripts/start-local-services-nacos.ps1` 默认连同 Gateway 一起启动，可用 `-WithoutGateway` 跳过
- `scripts/stop-local-services.ps1` 增加停止 `8080`
- `scripts/verify-nacos-services.ps1` 默认校验四个服务
- `scripts/smoke-gateway.ps1` 新增网关冒烟测试

## 前端联调改动

`food-life-agent-web/vite.config.ts` 已经从“分别代理到三个服务”改为“统一代理到 Gateway”。

保留前端原有调用前缀：

- `/user-api`
- `/business-api`
- `/trade-api`

Vite 代理会重写成后端真实路径并交给 `http://localhost:8080`。

## 生产化意义

这一步贴近面试和真实项目中的微服务入口设计：

- 前端不感知后端服务拆分
- 后端服务可以水平扩容，网关通过服务名负载均衡
- 后续可以在网关继续加限流、灰度、统一鉴权、链路追踪、熔断降级
- Agent 服务未来接入时，也可以通过网关统一暴露 `/api/agent/**`

## 下一步建议

- 统一请求日志字段规范
