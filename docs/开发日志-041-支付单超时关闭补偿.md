# 开发日志 041：支付单超时关闭补偿

## 本次目标

上一阶段已经有支付单表 `payment_order` 和模拟支付回调：

```text
PREPARED -> SUCCESS
```

但待支付订单超时以后，之前主要处理的是订单侧取消，支付单本身可能还停留在 `PREPARED`。

本次补齐支付单侧的超时关闭补偿：

```text
payment_order.PREPARED -> payment_order.CLOSED
dining_order.WAIT_PAY -> dining_order.CANCELED
```

当前仍然是本地模拟支付骨架，不接真实支付宝、微信或支付中心查询。

## 业务流程

1. 定时任务或手动接口触发支付单超时关闭。
2. 按 `payment_order.pay_status = PREPARED` 和 `create_time <= now - timeoutMinutes` 扫描待关闭支付单。
3. 对每一笔支付单执行 CAS 更新：

```text
PREPARED -> CLOSED
```

4. 根据支付单中的 `orderId + userId` 查询交易订单。
5. 如果订单仍是 `WAIT_PAY`，复用已有 `OrderDomainService.cancelOrder` 取消订单。
6. 订单取消后继续走已有业务：

```text
普通购买：取消订单 + 释放优惠券 + 发送套餐库存释放本地消息
拼团：取消未支付拼团锁单
秒杀：取消未支付秒杀单 + 释放活动库存
```

7. 返回本轮补偿统计和每一笔支付单的处理明细。

## 为什么先关闭支付单

当前选择先把支付单从 `PREPARED` 关闭为 `CLOSED`，再取消订单。

原因是支付回调入口会用支付单状态做 CAS：

```text
PREPARED -> SUCCESS
```

支付单先关闭以后，迟到的模拟回调无法再把支付单置为成功，可以避免“订单已经超时取消，但支付回调又成功结算”的冲突。

这个方案的边界也很清楚：如果支付单关闭成功后，订单取消过程出现异常，明细里会记录 `failReason`。后续接真实支付中心时，应增加支付渠道查询、关闭结果表或补偿重试任务，把这类异常做成可恢复流程。

### 领域服务

`PaymentOrderTimeoutCloseService`

职责：

1. 计算超时时间线。
2. 扫描超时 `PREPARED` 支付单。
3. 关闭支付单。
4. 复用订单取消领域服务处理不同订单类型的取消回滚。
5. 汇总补偿结果。

这里没有把普通购买、拼团、秒杀的取消逻辑重新写一遍，而是统一调用已经存在的 `cancelOrder`，保持业务规则只有一个入口。

### 仓储

`IPaymentOrderRepository` 新增：

```java
List<PaymentOrderEntity> listTimeoutPreparedPaymentOrders(LocalDateTime timeoutBefore, Integer limit);

boolean markPayClosed(String payOrderNo, String fromStatus);
```

`PaymentOrderRepository` 实现：

```text
扫描：pay_status = PREPARED and create_time <= timeoutBefore
关闭：pay_order_no = ? and pay_status = PREPARED
```

关闭使用状态条件更新，避免并发回调和补偿重复执行。

### 触发层接口

新增手动补偿接口：

```http
POST /api/trade/pay/orders/timeout/close?timeoutMinutes=30&limit=50
```

接口返回：

```text
scannedPaymentCount
closedPaymentCount
canceledOrderCount
failedPaymentCount
details
```

### 定时任务

新增 `PaymentOrderTimeoutCloseJob`：

```yaml
food:
  trade:
    payment:
      order-timeout-close:
        enabled: true
        fixed-delay-ms: 60000
        timeout-minutes: 30
```

每 60 秒扫描一次 30 分钟前仍未成功支付的支付单。

## 本地验证

验证主链路：

1. 登录测试用户。
2. 领取一张套餐范围优惠券。
3. 创建普通购买待支付订单。
4. 创建支付单，支付单状态为 `PREPARED`。
5. 手动把支付单 `create_time` 改到 31 分钟前。

7. 校验支付单为 `CLOSED`。
8. 校验订单为 `CANCELED`。
