## 当前事务治理分层

| 场景 | 方案 | 说明 |
| --- | --- | --- |
| 单服务写库 | 本地事务 | 使用 `@Transactional` |
| 普通购买 | 本地事务 + 库存远程预占 + RabbitMQ + 补偿 | 最终一致 |
| 秒杀 | Sentinel + Redis 预扣 + 请求单 + 异步处理 + 补偿 | 高并发削峰 |
| 拼团 | 锁单 + 支付推进 + 超时补偿 + 退款策略 | 状态机 + 补偿 |
| 运营库存调整 | Seata AT | 低并发强一致业务 |

## Seata 本地配置

配置位置：

- `food-trade-service/food-trade-app/src/main/resources/application-local.yml`
- `food-business-service/food-business-app/src/main/resources/application-local.yml`
- `deploy/nacos/configs/food-common.yaml`

默认关闭：

```yaml
seata:
  enabled: ${SEATA_ENABLED:false}
```

开启方式：

```powershell
$env:SEATA_ENABLED="true"
$env:SEATA_SERVER_ADDR="127.0.0.1:8091"
$env:SEATA_TX_GROUP="food-life-agent-tx-group"
```

兼容 Spring Cloud Alibaba 的配置：

```yaml
spring:
  cloud:
    alibaba:
      seata:
        tx-service-group: ${SEATA_TX_GROUP:food-life-agent-tx-group}
```

## 运营库存调整接口

外部入口：

```http
POST /api/trade/operations/package-stock-adjustments
authorization: {token}
Content-Type: application/json

{
  "packageId": 1,
  "adjustQuantity": 5,
  "reason": "local operation stock adjust",
  "operationId": "OPERATION_STOCK_ADJUST_001"
}
```

内部 Feign 接口：

```http
POST /api/internal/package/{packageId}/stock/adjust
```

内部接口说明：

- 由 `trade-service` Feign 调 `business-service`。
- Gateway 不路由 `/api/internal/**`。
- Gateway 黑名单新增 `/api/internal/**`。
- business-service 放行 `/api/internal/package/**`，作为服务内网调用入口。

## food_trade_db

### trade_operation_stock_adjust_log

用途：

- 记录运营库存调整链路的本地操作审计。
- 作为幂等判断依据。
- 与 business-service 的库存调整处于同一个全局事务中。

字段：

| 字段 | 说明 |
| --- | --- |
| id | 主键 |
| operation_id | 幂等操作号，唯一 |
| operator_id | 操作用户 |
| package_id | 套餐 ID |
| adjust_quantity | 调整库存数量，可正可负 |
| reason | 调整原因 |
| stock | 调整后库存 |
| sold | 调整后销量 |
| tx_status | PROCESSING/SUCCESS |
| create_time | 创建时间 |
| update_time | 更新时间 |

索引：

```sql
UNIQUE KEY uk_operation_id (operation_id)
KEY idx_package_id (package_id)
KEY idx_operator_time (operator_id, create_time)
```

### undo_log

用途：

- Seata AT 分支事务回滚日志。
- trade-service 作为全局事务发起方，同时也是本地数据库参与方。

## food_business_db

### package_stock_change_record

新增业务类型：

```text
ADMIN_ADJUST
```

用途：

- business-service 库存调整幂等。
- 与现有 `OCCUPY/RELEASE/CONFIRM_SOLD/ROLLBACK_SOLD` 共用同一张库存流水表。

幂等机制：

```sql
UNIQUE KEY uk_operation_id (operation_id)
```

### undo_log

用途：

- Seata AT 回滚 business-service 分支事务。
- business-service 修改 `meal_package.stock` 和写入 `package_stock_change_record` 时，Seata 通过数据源代理记录回滚镜像。

## 和 RabbitMQ 最终一致性的关系

运营库存调整链路不替代 RabbitMQ。

当前项目的定位是：

- 下单、秒杀、拼团：继续用最终一致性。
- 运营库存调整：用 Seata AT 做低并发强一致业务。

这样面试时能同时讲：

- 为什么不用分布式事务硬套高并发核心链路。
- 最终一致性如何靠消息、幂等、补偿保证。
- Seata AT 在低并发跨库强一致场景下如何落地。
