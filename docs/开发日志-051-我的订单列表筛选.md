# 开发日志-051-我的订单列表筛选

## 1. 本次目标

本次继续补齐网关前的非 Agent 业务能力，升级 `food-trade-service` 里的“我的订单列表”接口。

原接口：

```http
GET /api/trade/orders
authorization: {token}
```

原能力只支持基于 `lastId` 和 `pageSize` 的订单翻页，不支持按业务类型和订单状态筛选。真实 C 端订单中心一般会有：

```text
全部
待付款
已付款
已核销
已取消
已退款
普通购买
拼团
秒杀
```

所以本次保留原接口路径，新增可选查询条件。

## 2. 接口

```http
GET /api/trade/orders?tradeType=NORMAL&orderStatus=WAIT_PAY&pageSize=10&lastId=70
authorization: {token}
```

新增可选参数：

| 参数 | 说明 |
| --- | --- |
| `tradeType` | 订单业务类型 |
| `orderStatus` | 订单状态 |

支持的 `tradeType`：

```text
NORMAL
GROUP_BUY
SECKILL
```

支持的 `orderStatus`：

```text
WAIT_PAY
PAID
USED
CANCELED
REFUNDED
```

参数不传时，行为和原接口一致。

## 3. 业务流程

```text
1. 从 UserHolder 获取当前登录用户。
2. 校验用户是否登录。
3. 规范化 tradeType 和 orderStatus，支持小写入参。
4. 校验 tradeType 是否属于当前支持的三种业务类型。
5. 校验 orderStatus 是否属于当前订单状态机。
6. 通过 userId、lastId、tradeType、orderStatus 查询当前用户订单。
7. 查询每个订单的首个订单明细，补充店铺名、套餐名、封面快照。
8. 返回订单列表和游标翻页信息。
```

## 5. 查询规则

本次没有新增业务状态，只复用已有状态常量。

`tradeType` 校验放在领域服务：

```text
NORMAL / GROUP_BUY / SECKILL
```

`orderStatus` 校验放在领域服务：

```text
WAIT_PAY / PAID / USED / CANCELED / REFUNDED
```

仓储层只接收领域层规范化后的值，动态追加 SQL 条件。

## 8. 到网关前的意义

订单中心是网关接入前必须稳定下来的核心 C 端查询接口。

后续做微服务网关时，网关只需要把：

```text
/api/trade/orders/**
```

路由到 `food-trade-service`，不需要承担订单筛选、状态解释、快照补全等业务逻辑。
