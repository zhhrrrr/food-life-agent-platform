# 开发日志-047-用户关注关系闭环

## 1. 本次目标

本次在 `food-user-service` 内新增用户关注关系能力，继续复用黑马点评里的登录态方式：

```text
请求携带 authorization Token
food-auth-starter 解析 Redis Token
UserHolder 写入当前登录用户
关注接口从 UserHolder 获取 userId
```

本次不涉及 Agent，只补齐非 Agent 业务能力。

## 2. 新增接口

```http
POST /api/user/follows/{followUserId}
DELETE /api/user/follows/{followUserId}
GET /api/user/follows/{followUserId}/status
GET /api/user/follows?pageSize=10
GET /api/user/fans?pageSize=10
GET /api/user/follows/common/{targetUserId}?pageSize=10
```

## 3. 业务规则

```text
1. 必须登录，userId 只从 UserHolder 获取，不允许前端传入。
2. 不允许关注自己。
3. 关注前校验被关注用户必须存在且正常。
4. 重复关注保持幂等，最终 follow_status = 1。
5. 重复取消关注保持幂等，最终 follow_status = 0。
6. 关注列表查询当前用户主动关注的人。
7. 粉丝列表查询关注当前用户的人。
8. 共同关注查询当前用户和目标用户都关注的人。
```

## 4. 数据表

数据库：`food_user_db`

新增表：`user_follow`

脚本：

```text
docs/sql/food_user_db.sql
docs/sql/food_user_db_migration_047_user_follow.sql
```

表结构摘要：

| 字段 | 说明 |
| --- | --- |
| `id` | 关注关系 ID |
| `user_id` | 发起关注的用户 ID |
| `follow_user_id` | 被关注的用户 ID |
| `follow_status` | 1 关注中，0 已取消 |
| `create_time` | 创建时间 |
| `update_time` | 更新时间 |

核心约束：

```sql
UNIQUE KEY uk_user_follow (user_id, follow_user_id)
```

这保证同一用户对同一目标用户只有一条关系记录，取消关注不物理删除，只更新状态，便于后续做关系恢复、统计和审计。

## 6. 当前设计取舍

本次没有把关注关系放进 Redis Set 作为主实现，而是先以 MySQL 为准。

原因：

```text
1. 当前项目已经切到本地 MySQL 主存储。
2. 关系表需要幂等、状态恢复、分页、粉丝列表和后续审计，MySQL 更稳。
3. Redis Set 适合后续作为共同关注、Feed 推荐、用户关系缓存的加速层，而不是当前第一版主数据源。
```

后续如果要更贴近黑马点评共同关注的性能写法，可以在关注成功后同步：

```text
food:user:follow:{userId}
```

类型为 Redis Set，值为被关注用户 ID，然后用 `SINTER` 做共同关注。
