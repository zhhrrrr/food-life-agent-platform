# 开发日志 012：迁移 xfg 拼团设计模式模板

## 一、本次修正

上一版 `food-domain-patterns` 是自定义抽象的责任链、策略、规则树、流程模板。

本次按项目要求修正为：

```text
直接迁移 xfg 拼团项目使用的设计模式模板结构，
不再使用自写的 BusinessChainRouter、BusinessStrategyRouter、RuleTreeRouter、BusinessProcessTemplate。
```

迁移来源：

```text
group-buy-market
cn.bugstack.wrench:xfg-wrench-starter-design-framework:3.0.0
```

xfg 拼团项目中的典型使用：

```text
交易锁单规则过滤：LinkArmory + BusinessLinkedList + ILogicHandler
交易结算规则过滤：LinkArmory + BusinessLinkedList + ILogicHandler
交易退款规则过滤：LinkArmory + BusinessLinkedList + ILogicHandler
活动试算规则树：AbstractMultiThreadStrategyRouter + StrategyHandler
```

## 三、迁移的 link.model1

位置：

```text
food-domain-patterns/src/main/java/com/foodlife/patterns/framework/link/model1
```

迁移类：

```text
ILogicChainArmory
ILogicLink
AbstractLogicLink
```

作用：

```text
链式责任链模型 1。
```

特点：

```text
节点通过 appendNext 手动串起来，
每个节点继承 AbstractLogicLink，
节点内部主动调用 next(requestParameter, dynamicContext)。
```

对应 xfg 示例：

```text
group-buy-market-app/src/test/java/cn/bugstack/test/types/rule01
```

## 四、迁移的 link.model2

位置：

```text
food-domain-patterns/src/main/java/com/foodlife/patterns/framework/link/model2
```

迁移类：

```text
handler/ILogicHandler
chain/ILink
chain/LinkedList
chain/BusinessLinkedList
LinkArmory
```

作用：

```text
链式责任链模型 2。
```

特点：

```text
LinkArmory 负责组装责任链；
BusinessLinkedList 负责按链表顺序执行节点；
ILogicHandler 是业务规则过滤节点；
节点返回 null 表示继续向后执行；
节点返回非 null 表示提前结束链路并返回结果。
```

对应 xfg 拼团正式业务：

```text
TradeLockRuleFilterFactory
TradeSettlementRuleFilterFactory
TradeRefundRuleFilterFactory
```

## 五、迁移的 tree

位置：

```text
food-domain-patterns/src/main/java/com/foodlife/patterns/framework/tree
```

迁移类：

```text
StrategyHandler
StrategyMapper
AbstractStrategyRouter
AbstractMultiThreadStrategyRouter
```

作用：

```text
策略树 / 规则树路由模板。
```

特点：

```text
StrategyHandler 是具体规则节点；
StrategyMapper 根据上下文选择下一个节点；
AbstractStrategyRouter 提供普通规则路由；
AbstractMultiThreadStrategyRouter 提供多线程数据准备 + 规则路由骨架。
```

对应 xfg 拼团正式业务：

```text
AbstractGroupBuyMarketSupport
DefaultActivityStrategyFactory
RootNode
SwitchNode
MarketNode
TagNode
EndNode
ErrorNode
```

## 七、trade-service 接入方式修正

订单创建校验现在改为 xfg `link.model2` 风格。

订单校验节点：

```text
OrderCreateCheckHandler
```

现在继承：

```text
ILogicHandler<OrderCreateContext, OrderCreateContext, Void>
```

命令参数校验节点：

```text
OrderCommandCheckHandler
```

套餐快照校验节点：

```text
PackageTradeCheckHandler
```

订单校验链：

```text
OrderCreateCheckChain
```

内部使用：

```text
LinkArmory
BusinessLinkedList
```

## 八、为什么没有继续用自写 group/order 路由

xfg 拼团的责任链不是通过：

```text
group + order + router
```

自动组装的。

它的方式是：

```text
在 Factory 中显式声明链路节点顺序，
通过 LinkArmory 组装 BusinessLinkedList。
```

因此本次 trade-service 也按这个方式修正。

## 十、本次结论

当前 `food-domain-patterns` 已经不是自写模板，而是按 xfg 拼团项目的 `xfg-wrench-starter-design-framework` 迁移出的公共模板模块。

后续拼团、秒杀、Agent 权限、Agent 任务规则要使用设计模式模板时，优先使用：

```text
com.foodlife.patterns.framework.link.model2
com.foodlife.patterns.framework.tree
```

与 xfg 拼团项目保持同一套开发范式。
