# 开发日志 090 - P0 生产化闭环改造

## 背景

本阶段先不接真实支付宝，先把本地支付、退款、权限、契约、错误码、E2E 联调做到能跑通。目标不是继续写演示代码，而是把当前业务链路改造成更接近公司项目的形态。

## 本次完成

### 1. 本地支付从 mock 升级为可校验边界

新增支付回调签名字段：

```text
signType
signature
```

后端 `LocalPaymentProvider` 会校验：

```text
金额必须匹配 payment_order.pay_amount
signType 只支持 SHA256
signature 必须等于服务端按密钥计算出的签名
```

签名密钥显式放入本地配置和 Nacos 公共配置：

```text
food.payment.local.callback-secret
```

### 2. 退款从状态修改升级为退款单流程

新增 `refund_order` 表，退款主流程变为：

```text
订单状态校验
查询支付单
创建或读取退款单
调用 PaymentProvider.refund
退款单 PREPARED -> SUCCESS
支付单 SUCCESS -> REFUNDED
发送 payment.refunded 事件
释放优惠券
普通订单回滚套餐销量和库存
返回退款单号和渠道退款号
```

### 3. 用户角色改为表驱动

新增 `user_role` 表。用户登录后写入 Redis Token 的 `role` 不再固定为 `USER`，而是从数据库读取最高角色。

角色优先级：

```text
ADMIN > OPERATOR > USER
```

### 4. 错误码治理细化

trade-service 增加业务错误码：

```text
ORDER_409
PAYMENT_401
PAYMENT_502
```

`GlobalExceptionHandler` 会根据异常语义映射到对应错误码，前端和脚本可以根据 code 判断失败类型。

### 5. P0 业务级 E2E 脚本

新增：

```text
scripts/smoke-p0-business-flow.ps1
```

这条脚本跑完整业务，不只是插数据：

```text
登录 -> 授权 -> 下单 -> 支付 -> 核销 -> 评价 -> 再下单 -> 支付 -> 退款 -> 对账 -> 审计查询
```

同时修复旧 RabbitMQ smoke 脚本，使支付回调也走新签名规则。

### 6. Flyway MySQL 真实运行适配

Boot 3 使用的 Flyway 9 对数据库支持进行了模块拆分。为了让本地 MySQL 8.0 真实执行迁移，三个 app 模块补充：

```text
org.flywaydb:flyway-mysql
```

涉及模块：

```text
food-user-app
food-business-app
food-trade-app
```
