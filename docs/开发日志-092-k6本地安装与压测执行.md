# 开发日志-092-k6 本地安装与压测执行

## 本次目标

把上一步只生成脚本、未执行的 k6 压测补齐为真实可运行状态。

## 完成内容

1. 本机安装 k6 到项目本地目录 `tools/k6/k6.exe`。
2. 新增 `scripts/install-k6-local.ps1`，用于新环境一键下载并安装 k6。
3. 改造 `scripts/run-k6-food-flows.ps1`：
   - 优先使用系统 PATH 中的 `k6`。
   - 如果系统未安装，则使用项目内 `tools/k6/k6.exe`。
   - 未传 `-AuthToken` 时自动调用登录接口、读取 Redis 验证码、获取 token。
   - 每条压测链路输出 summary 到 `logs/k6`。
4. 改造三条 k6 脚本，支持 `smoke` 和 `load` 两档：
   - `smoke`：本地低强度验证，避免打空库存。
   - `load`：正式压测强度，用于观察限流、库存、MQ 和数据库表现。

## 压测链路

| 链路 | 脚本 | 默认 smoke 强度 |
| --- | --- | --- |
| 普通下单 | `scripts/k6/normal-order.js` | 低速 ramping arrival rate |
| 拼团下单 | `scripts/k6/group-buy-order.js` | 低并发 ramping VUs |
| 秒杀异步下单 | `scripts/k6/seckill-order.js` | 3 RPS，持续 15 秒 |

## 使用方式

```powershell
.\scripts\install-k6-local.ps1
.\scripts\run-k6-food-flows.ps1 -Profile smoke -PackageId 1 -ActivityId 1
```

正式压测时切换为：

```powershell
.\scripts\run-k6-food-flows.ps1 -Profile load -PackageId 1 -ActivityId 1
```

## 说明

`tools/` 已在 `.gitignore` 中，所以 k6 二进制不会提交到仓库。仓库只保留安装脚本、运行脚本和压测脚本。
