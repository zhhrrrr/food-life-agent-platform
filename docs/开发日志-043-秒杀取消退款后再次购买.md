# 开发日志 043：秒杀取消退款后再次购买

## 本次目标

秒杀订单取消或退款后，用户应该可以再次参与同一个秒杀活动。

之前 Java 侧限购已经只统计活跃订单：

```text
WAIT_PAY
PAID
```

但数据库上还有唯一索引：

```text
uk_user_activity(user_id, activity_id)
```

这个索引会把历史 `CANCELED / REFUNDED` 订单也挡住，导致用户即使释放了库存和 Redis 占位，也不能再次下单。

## 调整方案

把 `seckill_order` 的唯一索引改为普通查询索引：

```text
idx_user_activity_status(user_id, activity_id, order_status)
```

这样历史单可以保留，业务限购由下面两层控制：

```text
Redis Lua 用户占位
MySQL WAIT_PAY/PAID 活跃订单计数
```

## 数据规则

计入限购：

```text
seckill_order.order_status = WAIT_PAY
seckill_order.order_status = PAID
```

不计入限购：

```text
seckill_order.order_status = CANCELED
seckill_order.order_status = REFUNDED
```

## 业务流程

取消后再次购买：

```text
秒杀下单 -> WAIT_PAY
取消订单 -> CANCELED
释放 MySQL 库存
释放 Redis 库存和用户占位
再次下单成功
```

退款后再次购买：

```text
秒杀下单 -> WAIT_PAY
支付成功 -> PAID
退款成功 -> REFUNDED
释放 MySQL 库存
释放 Redis 库存和用户占位
再次下单成功
```

活跃订单仍然限购：

```text
已有 WAIT_PAY 或 PAID 秒杀单
再次下单返回 seckill user take limit
```

## 本次改动

主建表脚本：

```text
docs/sql/food_trade_db.sql
```

迁移脚本：

```text
docs/sql/food_trade_db_migration_043_seckill_rebuy_after_close.sql
```

迁移内容：

```sql
ALTER TABLE seckill_order
  DROP INDEX uk_user_activity,
  ADD INDEX idx_user_activity_status (user_id, activity_id, order_status);
```

Java 主业务逻辑不需要改，因为 `queryUserTakeCount` 已经只统计 `WAIT_PAY / PAID`。

## 当前边界

MySQL 8 不支持直接创建“只对 WAIT_PAY/PAID 生效”的部分唯一索引。

当前阶段采用：

```text
Redis Lua 原子占位
MySQL 活跃订单计数兜底
取消/退款释放 Redis 占位
```

后续如果做压测和高并发生产化，可以继续补：

```text
请求幂等号
用户活动活跃占位表
活动限购流水
MQ 最终一致释放
并发压测用例
```
