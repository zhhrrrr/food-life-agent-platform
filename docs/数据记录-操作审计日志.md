# 数据记录-操作审计日志

## 所属数据库

`food_trade_db`

## 表名

`trade_operation_audit_log`

## 建表脚本

- `docs/sql/food_trade_db.sql`
- `docs/sql/food_trade_db_migration_080_operation_audit_log.sql`

## 字段说明

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | BIGINT | 主键 |
| trace_id | VARCHAR(64) | 全链路追踪 ID |
| operator_id | BIGINT | 操作人用户 ID |
| operator_role | VARCHAR(32) | 操作人角色 |
| operation_type | VARCHAR(64) | 操作类型 |
| biz_type | VARCHAR(64) | 业务对象类型 |
| biz_id | VARCHAR(128) | 业务对象 ID |
| operation_status | VARCHAR(32) | 操作结果 |
| request_content | TEXT | 请求快照 |
| response_content | TEXT | 响应快照 |
| remark | VARCHAR(255) | 备注 |
| create_time | DATETIME | 创建时间 |

## 当前操作类型

| operation_type | 触发接口 | 说明 |
| --- | --- | --- |
| PAYMENT_PREPARE | POST /api/trade/pay/orders/{orderId}/prepare | 创建或复用支付单 |
| PAYMENT_CALLBACK_MOCK | POST /api/trade/pay/callback/mock | 本地 mock 支付回调 |
| ORDER_CANCEL | POST /api/trade/orders/{orderId}/cancel | 用户取消订单 |
| ORDER_PAY_MOCK | POST /api/trade/orders/{orderId}/pay/mock | 旧版本地 mock 支付 |
| USER_REFUND_APPLY | POST /api/trade/orders/{orderId}/refund/apply | 用户申请退款 |
| OPERATION_REFUND_CONFIRM | POST /api/trade/orders/{orderId}/refund/confirm | 运营确认退款 |
| ORDER_USE_MOCK | POST /api/trade/orders/{orderId}/use/mock | 到店核销 |
| OPERATION_STOCK_ADJUST | POST /api/trade/operations/package-stock-adjustments | 运营调整套餐库存 |

## 查询接口

```text
GET /api/trade/operations/audit-logs
```

支持参数：

| 参数 | 说明 |
| --- | --- |
| traceId | 按链路 ID 查询 |
| operatorId | 按操作人查询 |
| operationType | 按操作类型查询 |
| bizType | 按业务对象类型查询 |
| bizId | 按业务对象 ID 查询 |
| limit | 返回条数，默认 50，最大 200 |

权限：

- 路径命中 `/api/trade/operations/**`
- 需要 `ADMIN` 或 `OPERATOR`

## 索引设计

| 索引 | 字段 | 用途 |
| --- | --- | --- |
| idx_trace_id | trace_id | 根据链路追踪 ID 查询审计记录 |
| idx_operator_time | operator_id, create_time | 查询某个操作人的操作历史 |
| idx_biz | biz_type, biz_id | 查询某个订单或套餐库存的操作历史 |
| idx_operation_time | operation_type, create_time | 按操作类型排查问题 |

## 设计原则

- 审计记录不替代业务表。
- 审计失败不阻断支付、退款、核销主流程。
- 审计记录用于排查问题、面试展示、后续运营后台查询和 Agent 写操作追踪。
