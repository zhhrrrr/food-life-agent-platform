## 八、当前数据风险和注意事项

### 1. 当前 Redis 用户数据只是临时方案

当前 Redis 保存用户数据是为了快速跑通登录闭环，不是最终用户主数据方案。

最终用户主数据应该进入 MySQL。

### 2. Token 中不要存敏感数据

当前 Token Hash 只保存：

```text
id
nickName
icon
```

不要保存：

```text
手机号明文
密码
支付信息
身份证
地址
```

### 3. Redis Key 要统一前缀

当前统一使用：

```text
food:
```

避免和黑马点评原项目 `login:`、`cache:` 等 Key 冲突。

### 4. 本地运行必须启动 Redis

如果 Redis 没启动：

```text
/api/user/code
/api/user/login
/api/user/me
```

都会无法完整验证。

## 十四、秒杀异步恢复与库存对账

### 1. 卡死消息恢复

扫描：

```text
trade_local_message.message_type = SECKILL_ORDER_CREATE
trade_local_message.message_status = PROCESSING
trade_local_message.update_time <= now - 120s
```

恢复：

```text
message_status -> INIT
retry_count + 1
next_retry_time -> now
fail_reason -> recover stuck processing message
```

### 2. 超时请求取消

扫描：

```text
seckill_order_request.request_status in (INIT, PROCESSING)
seckill_order_request.order_id is null
seckill_order_request.create_time <= now - 300s
```

取消：

```text
request_status -> FAILED
fail_reason -> seckill order request timeout
释放 Redis 库存和用户占位
```

## 十七、普通套餐库存销量补偿与幂等

普通订单状态在 `food_trade_db`，套餐库存和销量在 `food_business_db`。为了降低跨服务同步失败带来的不一致，本次新增普通套餐库存销量补偿骨架。

### 1. business-service 幂等记录表

表名：

```text
package_stock_change_record
```

所属数据库：

```text
food_business_db
```

用途：

```text
记录 business-service 已经执行过的套餐库存/销量动作。
通过 operation_id 做幂等，避免补偿任务重复执行同一个动作。
```

核心字段：

```text
operation_id
package_id
quantity
change_type
change_status
```

`change_type` 当前取值：

```text
OCCUPY
RELEASE
CONFIRM_SOLD
ROLLBACK_SOLD
```

### 2. business-service 幂等接口

库存销量接口新增可选参数：

```http
POST /api/package/{packageId}/stock/occupy?quantity=1&operationId=xxx
POST /api/package/{packageId}/stock/release?quantity=1&operationId=xxx
POST /api/package/{packageId}/sold/confirm?quantity=1&operationId=xxx
POST /api/package/{packageId}/sold/rollback?quantity=1&operationId=xxx
```

不传 `operationId` 时仍按普通同步接口执行。

传 `operationId` 时：

```text
已处理过相同 operationId 且参数一致：直接返回当前库存销量结果。
已处理过相同 operationId 但参数不一致：拒绝执行。
未处理过：执行业务变更并记录幂等流水。
```

### 4. 普通订单消息产生规则


### 2. 为什么不能只靠反向计算

`shop.score` 当前是十分制整数，例如 `46` 表示 `4.6` 分。

如果使用整数平均分反向计算，可能因为取整导致删除评价后无法回到创建前的准确值。

因此新评价创建时会保存：

```text
shop_comments_before
shop_score_before
```

隐藏评价时优先直接恢复这两个快照。
