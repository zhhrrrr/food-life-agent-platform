## 八、当前数据风险和注意事项

### 1. 当前 Redis 用户数据只是临时方案

当前 Redis 保存用户数据是为了快速跑通登录闭环，不是最终用户主数据方案。

最终用户主数据应该进入 MySQL。

### 2. Token 中不要存敏感数据

当前 Token Hash 只保存：

```text
id
nickName
icon
```

不要保存：

```text
手机号明文
密码
支付信息
身份证
地址
```

### 3. Redis Key 要统一前缀

当前统一使用：

```text
food:
```

避免和黑马点评原项目 `login:`、`cache:` 等 Key 冲突。

### 4. 本地运行必须启动 Redis

如果 Redis 没启动：

```text
/api/user/code
/api/user/login
/api/user/me
```

都会无法完整验证。

## 十四、秒杀异步恢复与库存对账

### 1. 卡死消息恢复

扫描：

```text
trade_local_message.message_type = SECKILL_ORDER_CREATE
trade_local_message.message_status = PROCESSING
trade_local_message.update_time <= now - 120s
```

恢复：

```text
message_status -> INIT
retry_count + 1
next_retry_time -> now
fail_reason -> recover stuck processing message
```

### 2. 超时请求取消

扫描：

```text
seckill_order_request.request_status in (INIT, PROCESSING)
seckill_order_request.order_id is null
seckill_order_request.create_time <= now - 300s
```

取消：

```text
request_status -> FAILED
fail_reason -> seckill order request timeout
释放 Redis 库存和用户占位
```

### 3. 库存对账

接口：

```http
POST /api/trade/seckill/activities/{activityId}/stock/reconcile
```

规则：

```text
以 MySQL seckill_activity.stock 为准刷新 Redis。
```

### 4. 恢复任务配置

```yaml
food:
  trade:
    seckill:
      order-request-recovery:
        enabled: true
        fixed-delay-ms: 60000
```

## 十六、普通套餐库存销量数据闭环

本次新增普通购买对 `food_business_db` 中基础套餐库存和销量的影响。

### 1. 涉及数据库

```text
food_business_db
food_trade_db
```

`food_business_db` 维护店铺和套餐主数据：

```text
meal_package.stock  可售库存
meal_package.sold   套餐销量
shop.sold           店铺销量
```

`food_trade_db` 维护交易数据：

```text
dining_order        订单主表
dining_order_item   订单明细快照
```

### 2. 普通购买数据变化

```text
创建普通订单成功：
meal_package.stock = stock - quantity
dining_order.order_status = WAIT_PAY

取消未支付普通订单：
dining_order.order_status = CANCELED
meal_package.stock = stock + quantity

支付普通订单：
dining_order.order_status = PAID
meal_package.sold = sold + quantity
shop.sold = sold + quantity

退款普通订单：
dining_order.order_status = REFUNDED
meal_package.sold = sold - quantity
shop.sold = sold - quantity
meal_package.stock = stock + quantity
```

### 3. 当前接口

```http

POST /api/package/{packageId}/stock/release?quantity=1
POST /api/package/{packageId}/sold/confirm?quantity=1
POST /api/package/{packageId}/sold/rollback?quantity=1
```

当前普通订单状态和套餐库存销量跨两个微服务数据库，暂时通过同步 HTTP 调用完成数据闭环。
