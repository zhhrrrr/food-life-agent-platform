# 开发日志-050-店铺主页聚合接口

## 1. 本次目标

本次继续补齐网关前的非 Agent 业务能力，在 `food-business-service` 内新增店铺主页聚合查询。

之前已有分散接口：

```text
GET /api/shop/{id}
GET /api/package/of/shop?shopId=1
GET /api/shop/{shopId}/review-summary
GET /api/favorites/shops/{shopId}/status
```

这些接口分别能查店铺、套餐、评价摘要、收藏状态，但真实 C 端进入店铺详情页时，一般需要一次性拿到上述数据。本次新增一个用户态聚合入口，给后续前端、移动端和微服务网关接入做准备。

## 2. 新增接口

```http
GET /api/shop-homepage/{shopId}
authorization: {token}
```

返回核心字段：

```text
userId
shop
packages
favorite
reviewSummary
```

说明：

```text
该接口需要登录，因为会返回当前用户对店铺的 favorite 状态。
公开店铺查询仍然保留原来的 /api/shop/** 和 /api/package/**。
```

## 3. 业务流程

```text
1. 从 UserHolder 获取当前登录用户。
2. 校验 userId 和 shopId。
3. 查询店铺基础信息。
4. 店铺不存在则返回 shop not found。
5. 查询店铺下可售套餐列表。
6. 查询店铺评价摘要和最近 3 条评价。
7. 查询当前用户是否收藏该店铺。
8. 聚合返回店铺主页 DTO。
```

## 5. 复用关系

本次没有重复实现底层查询规则，而是复用已有领域服务：

```text
ShopDomainService          查询店铺
PackageDomainService       查询店铺套餐
ShopReviewDomainService    查询最近评价
ShopFavoriteDomainService  查询当前用户收藏状态
```

这样保持业务规则仍然在原有领域服务中，主页聚合只负责组织读模型。

返回数据摘要：

```text
shop.name = Chengdu Spicy Hot Pot
packages.size = 2
reviewSummary.latestReviews.size = 1
favorite 支持跟随当前用户收藏关系变化
```

## 8. 到网关前的意义

这个接口是典型的服务内读模型聚合：

```text
业务拼装放在 business-service，不放到未来 gateway。
gateway 后续只负责统一入口、路由、鉴权透传、限流和跨域等网关职责。
```

因此这一步属于微服务网关之前应该完成的业务 API 准备。
