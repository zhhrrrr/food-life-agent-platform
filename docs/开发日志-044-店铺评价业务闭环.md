# 开发日志 044：店铺评价业务闭环

## 一、本次目标

本次先不做 Agent，继续补齐美食生活项目里不涉及 Agent 的业务能力。

这一步完成的是 `business-service` 的店铺评价闭环：

1. 用户必须登录后才能创建评价。
2. 评价必须绑定真实订单。
3. 只有当前用户自己的已核销订单才能评价。
4. 同一订单只能评价一次。
5. 评价成功后写入 `shop_review`。
6. 同步更新 `shop.comments` 和 `shop.score` 聚合字段。
7. 支持店铺评价列表和我的评价列表查询。

## 二、服务边界

评价数据放在 `food-business-service`。

原因：

- 评价是围绕店铺和套餐的内容型数据，归店铺业务域更合理。
- 订单是否已支付、是否已核销，仍然归 `food-trade-service` 判断。
- `business-service` 创建评价前通过 HTTP 调用 `trade-service` 的订单详情接口，不跨库查询订单表。

当前边界：

| 服务 | 职责 |
| --- | --- |
| `food-business-service` | 保存评价、查询评价、维护店铺评价数和评分 |
| `food-trade-service` | 校验订单归属、订单状态、套餐和店铺快照 |
| `food-user-service` | 登录与 Token 颁发，沿用黑马点评登录方式 |

## 三、业务流程

创建评价流程：

```text
用户携带 token 请求 business-service
  -> business-service 从 UserHolder 获取 userId
  -> 校验 orderId、score、content
  -> business-service 转发 token 调用 trade-service 查询订单详情
  -> trade-service 按当前 token 查询当前用户自己的订单
  -> business-service 判断订单状态必须是 USED
  -> 判断当前订单是否已经评价过
  -> 写入 shop_review
  -> 更新 shop.comments + 1
  -> 使用旧评论数和新评分重新计算 shop.score
  -> 返回评价结果
```

## 四、接口

### 1. 创建评价

```http
POST /api/reviews
authorization: {token}
Content-Type: application/json

{
  "orderId": 61,
  "score": 5,
  "content": "Good package, smooth verification, review flow test data.",
  "images": ""
}
```

成功响应：

```json
{
  "code": "0000",
  "message": "success",
  "data": {
    "reviewId": 1,
    "reviewNo": "RV178799035904043",
    "userId": 43,
    "shopId": 1,
    "packageId": 1,
    "orderId": 61,
    "orderNo": "NO178799035840243",
    "score": 5,
    "content": "Good package, smooth verification, review flow test data.",
    "images": "",
    "createTime": "2026-08-29T15:59:19"
  }
}
```

重复评价响应：

```json
{
  "code": "400",
  "message": "order already reviewed",
  "data": null
}
```

未核销订单评价响应：

```json
{
  "code": "400",
  "message": "order not used",
  "data": null
}
```

### 2. 店铺评价列表

```http
GET /api/shop/1/reviews?pageSize=5
```

店铺评价列表是公开查询接口，跟已有店铺详情、套餐列表一样放在 `/api/shop/**` 下。

### 3. 我的评价列表

```http
GET /api/reviews/my?pageSize=5
authorization: {token}
```
