# 开发日志-034：普通订单超时取消

## 一、开发目标

本次继续只做非 Agent 业务。

普通购买订单已经具备：

```text
创建订单
占用套餐库存
取消订单释放库存
支付成功确认销量
退款回滚销量并释放库存
库存销量本地消息补偿
链路聚合查询
```

本次补齐“未支付普通订单超时取消”能力，让系统可以像生产环境一样自动处理长时间停留在 `WAIT_PAY` 的普通订单。

## 二、业务规则

扫描条件：

```text
trade_type = NORMAL
order_status = WAIT_PAY
create_time <= 当前时间 - timeoutMinutes
```

处理动作：

```text
1. 查询超时未支付普通订单
2. 使用 CAS 更新订单状态：WAIT_PAY -> CANCELED
3. 取消成功后发送 NORMAL_PACKAGE_RELEASE_STOCK 本地消息
4. 本地消息调用 business-service 释放套餐库存
5. business-service 通过 operation_id 做幂等记录
```

幂等边界：

```text
订单状态更新使用 fromStatus=WAIT_PAY，避免重复取消。
库存释放通过 trade_local_message.message_id 去重。
business-service 通过 package_stock_change_record.operation_id 去重。
```

## 三、新增接口

### 1. 手动触发普通订单超时取消

```http
POST /api/trade/normal/orders/timeout/cancel?timeoutMinutes=30&limit=50
```

参数说明：

```text
timeoutMinutes  超时分钟数，默认 30，最小 1，最大 1440
limit           单次扫描数量，默认 50，最大 200
```

返回核心字段：

```text
compensateTime
timeoutMinutes
timeoutBefore
scannedOrderCount
canceledOrderCount
releaseStockMessageCount
failedOrderCount
details
```

### 2. 定时任务

配置位置：

```text
food-trade-service/food-trade-app/src/main/resources/application.yml
```

配置内容：

```yaml
food:
  trade:
    normal:
      order-timeout-cancel:
        enabled: true
        fixed-delay-ms: 60000
        timeout-minutes: 30
```

## 六、当前结论

普通购买订单已经补齐后台超时取消闭环。

这一步不是简单插入数据，而是真正新增了业务实现：

```text
系统自动发现超时订单
系统自动取消订单
系统自动释放库存
系统通过本地消息和 business-service 幂等记录保证重复执行不产生重复库存变更
```
