# 数据记录-认证与服务间安全

## Redis 登录数据

登录 token key：

```text
food:login:token:{token}
```

数据类型：

```text
Hash
```

字段：

```text
id
nickName
icon
```

TTL：

```text
30 minutes
```

刷新位置：

```text
food-auth-starter/src/main/java/com/foodlife/auth/interceptor/RefreshTokenInterceptor.java
```

## 用户请求 Header

前端请求统一携带：

```text
authorization: {token}
```

Gateway 兼容：

```text
Authorization: Bearer {token}
```

Gateway 转发给下游时归一化为：

```text
authorization: {token}
Authorization: {token}
```

## Gateway 可信用户上下文 Header

Gateway 从 Redis Hash 解析后写入：

```text
x-user-id
x-user-nickname
x-user-icon
```

这些 header 只作为网关限流、日志、观测和后续轻量上下文使用。

下游业务真正判断当前用户，仍然以 `food-auth-starter` 查询 Redis 后写入的 `UserHolder` 为准。

## Gateway 剥离的外部 Header

Gateway 会剥离客户端传入的：

```text
x-user-id
x-user-nickname
x-user-icon
x-internal-call
x-internal-secret
```

目的：

- 防止用户伪造身份 header。
- 防止用户伪造内部调用 header。

代码位置：

```text
food-gateway-service/src/main/java/com/foodlife/gateway/filter/GatewayAuthFilter.java
```

## 服务间内部调用 Header

## auth-starter 内部调用配置

本地配置位置：

```text
food-user-service/food-user-app/src/main/resources/application-local.yml
food-business-service/food-business-app/src/main/resources/application-local.yml
food-trade-service/food-trade-app/src/main/resources/application-local.yml
```

Nacos 配置位置：

```text
deploy/nacos/configs/food-common.yaml
deploy/nacos/configs/food-user-service.yaml
deploy/nacos/configs/food-business-service.yaml
deploy/nacos/configs/food-trade-service.yaml
```

配置内容：

```yaml
food:
  auth:
    internal-call:
      enabled: true
      paths:
        - /api/internal/**
      header-name: x-internal-call
      header-value: food-life-agent
      secret-header-name: x-internal-secret
      secret: ${FOOD_INTERNAL_SECRET:local-internal-secret}
```

## business-service 白名单变化

旧配置：

```yaml
exclude-paths:
  - /api/package/**
  - /api/internal/package/**
```

新配置：

```yaml
exclude-paths:
  - /api/package/*
  - /api/package/of/shop
  - /api/package/trade-snapshot/*
  - /api/internal/**
```

含义：

- 套餐公开查询保持免登录。
- 库存写接口不再因为 `/api/package/**` 被整体放开。
- `/api/internal/**` 不走用户登录校验，但必须通过 `InternalCallInterceptor` 的内部密钥校验。
## 认证白名单补充

auth-starter 默认白名单包含：

```text
/health
/error
/api/user/code
/api/user/login
/api/user/logout
```

`/error` 必须放行。否则 Controller 参数解析失败、JSON 请求体错误、未知异常等场景会先进入 Spring Boot `/error`，再被登录拦截器改写成 `401`，导致真实错误码被掩盖。

各服务配置中也显式补充了 `/error`：

```text
food-user-service/food-user-app/src/main/resources/application-local.yml
food-business-service/food-business-app/src/main/resources/application-local.yml
food-trade-service/food-trade-app/src/main/resources/application-local.yml
food-gateway-service/src/main/resources/application-local.yml
deploy/nacos/configs/food-user-service.yaml
deploy/nacos/configs/food-business-service.yaml
deploy/nacos/configs/food-trade-service.yaml
deploy/nacos/configs/food-gateway-service.yaml
```
