# 数据记录 - 秒杀数据

## 数据库

- 服务：`food-trade-service`
- 数据库：`food_trade_db`
- 新增表：`seckill_activity`、`seckill_order`
- 主订单仍使用：`dining_order`
- 订单明细仍使用：`dining_order_item`

## 表职责

| 表 | 职责 |
| --- | --- |
| `seckill_activity` | 记录套餐秒杀活动、秒杀价、活动时间窗、库存、用户限购 |
| `seckill_order` | 记录用户抢购成功后和交易订单的关系 |
| `dining_order` | 统一交易订单主表，秒杀订单 `trade_type = SECKILL` |
| `dining_order_item` | 统一交易订单明细，保存套餐交易快照 |

## 初始化数据

`seckill_activity` 本地初始化一条活动：

| 字段 | 值 |
| --- | --- |
| `package_id` | `1` |
| `activity_name` | `local seckill meal package` |
| `seckill_price` | `9800` |
| `activity_status` | `1` |
| `valid_start_time` | `2026-01-01 00:00:00` |
| `valid_end_time` | `2026-12-31 23:59:59` |
| `stock` | `20` |
| `user_take_limit` | `1` |

## 秒杀下单写入关系

接口：

```http
POST /api/trade/orders/seckill
```

请求：

```json
{
  "activityId": 1,
  "quantity": 1
}
```

写入流程：

1. 校验用户登录。
2. 校验 `activityId` 存在。
3. 校验 `quantity = 1`。
4. 校验活动启用、活动已开始、活动未结束、库存大于 0。
5. 校验当前用户在该活动下未超过 `user_take_limit`。
6. 远程查询套餐交易快照。
7. 按套餐原价计算 `total_amount`，按秒杀价计算 `pay_amount`。
8. 原子扣减秒杀活动库存：`seckill_activity.stock = stock - 1`。
9. 写入 `dining_order`，`trade_type = SECKILL`，`order_status = WAIT_PAY`。
10. 写入 `dining_order_item`。
11. 写入 `seckill_order`，`order_status = WAIT_PAY`。

## 秒杀支付写入关系

秒杀支付复用：

```http
POST /api/trade/orders/{orderId}/pay/mock
```

写入流程：

1. `dining_order.order_status` 从 `WAIT_PAY` 更新为 `PAID`。
2. `seckill_order.order_status` 从 `WAIT_PAY` 更新为 `PAID`。
3. 支付响应返回 `activityId`，便于 Agent 追踪业务来源。

## 秒杀未支付取消写入关系

秒杀取消复用：

```http
POST /api/trade/orders/{orderId}/cancel
```

写入流程：

1. `dining_order.order_status` 从 `WAIT_PAY` 更新为 `CANCELED`。
2. `seckill_order.order_status` 从 `WAIT_PAY` 更新为 `CANCELED`。
3. 恢复秒杀库存：`seckill_activity.stock = stock + 1`。

## 当前边界

- 当前已经从 MySQL 原子扣库存版本升级为 Redis + Lua 预占库存版本。
- MySQL 仍保留 `seckill_activity.stock = stock - 1` 作为最终落库兜底。
- Redis 承接秒杀入口库存判断和用户占位。
- 当前还没有引入 MQ 异步下单。
- 当前只允许 `quantity = 1`。
- 当前用户限购先由 Redis Lua 拦截，MySQL `seckill_order` 的 `WAIT_PAY / PAID` 记录继续兜底。
- 当前秒杀退款仍未单独扩展，后续可以按拼团退款策略继续补。

## 秒杀异步业务流

```text
1. POST /api/trade/orders/seckill/async
2. Redis Lua 扣库存并写用户占位。
3. 写入 seckill_order_request。
4. 写入 trade_local_message。
5. 返回 requestNo。
6. 定时任务或手动接口消费本地消息。
7. 创建 dining_order、dining_order_item、seckill_order。
8. 更新请求单 SUCCESS，并绑定 orderId/orderNo。
9. GET /api/trade/seckill/order-requests/{requestNo} 查询最终结果。
```

## 秒杀异步恢复数据

### 卡死消息恢复

扫描：

```text
trade_local_message.message_status = PROCESSING
trade_local_message.update_time <= now - 120s
```

恢复：

```text
message_status = INIT
retry_count = retry_count + 1
next_retry_time = now
fail_reason = recover stuck processing message
```

本地验证：

```text
message_id = MSG_RECOVERY_STUCK_2
message_status: PROCESSING -> INIT
retry_count: 0 -> 1
```

### 超时请求取消

扫描：

```text
seckill_order_request.request_status in (INIT, PROCESSING)
seckill_order_request.order_id is null
seckill_order_request.create_time <= now - 300s
```

取消：

```text
request_status = FAILED
fail_reason = seckill order request timeout
释放 Redis 库存和用户占位
```

本地验证：

```text
request_no = SK_RECOVERY_TIMEOUT_2
request_status: INIT -> FAILED
Redis stock: 16 -> 17
```

## 秒杀链路聚合查询数据

本次新增两个只读查询接口：

```http
GET /api/trade/seckill/order-requests/{requestNo}/trace
GET /api/trade/orders/{orderId}/seckill-trace
```

聚合读取的数据来源：

| 数据 | 来源 |
| --- | --- |
| 请求单 | `seckill_order_request` |
| 真实订单 | `dining_order` |
| 订单明细 | `dining_order_item` |
| 秒杀活动 | `seckill_activity` |
| MySQL 秒杀库存 | `seckill_activity.stock` |
| Redis 秒杀库存 | `food:trade:seckill:stock:{activityId}` |
| 待支付数量 | `seckill_order.order_status = WAIT_PAY` |
| 已支付数量 | `seckill_order.order_status = PAID` |
| 套餐快照 | `food-business-service /api/package/trade-snapshot/{packageId}` |

本地验证数据：

```text
request_no = SK178635256105433
order_id = 40
user_id = 33
request_status = SUCCESS

trade_type = SECKILL
```

`currentStage` 是面向 Agent 的统一状态：

| 状态来源 | currentStage |
| --- | --- |
| `seckill_order_request = INIT/PROCESSING` | `ORDER_CREATING` |
| `seckill_order_request = FAILED` | `REQUEST_FAILED` |
| 请求成功但订单查不到 | `ORDER_UNKNOWN` |
| `dining_order.order_status = WAIT_PAY` | `WAIT_PAY` |
| `dining_order.order_status = PAID` | `PAID` |
| `dining_order.order_status = USED` | `USED` |
| `dining_order.order_status = CANCELED` | `CANCELED` |
| `dining_order.order_status = REFUNDED` | `REFUNDED` |

## 秒杀已支付退款数据

退款入口：

```http
POST /api/trade/orders/{orderId}/refund/mock
```

退款前要求：

```text
dining_order.trade_type = SECKILL
dining_order.order_status = PAID
seckill_order.order_id = dining_order.id
seckill_order.order_status = PAID
```

退款成功后：

```text
dining_order.order_status = REFUNDED
seckill_order.order_status = REFUNDED
seckill_activity.stock = stock + 1
```

退款响应会返回：

```text
refundBehavior = success
orderStatus = REFUNDED
activityId = seckill_order.activity_id
```

重复退款沿用退款责任链：

```text
refundBehavior = repeat
orderStatus = REFUNDED
```

注意：当前恢复的是 MySQL `seckill_activity.stock`。Redis 秒杀库存可通过库存对账接口刷新：

```http
POST /api/trade/seckill/activities/{activityId}/stock/reconcile
```

本地验证数据：

```text
phone = 13900000942
userId = 39
activityId = 1
orderId = 55
orderNo = NO178797229667539
payAmount = 9800
```

支付后：

```text
dining_order.order_status = PAID
seckill_order.order_status = PAID
seckill_activity.stock = 29
```

退款后：

```text
dining_order.order_status = REFUNDED
seckill_order.order_status = REFUNDED
seckill_activity.stock = 30
refundBehavior = success
activityId = 1
```

重复退款：

```text
refundBehavior = repeat
orderStatus = REFUNDED
```

Redis 对账：

```text
dbStock = 30
redisStockBefore = 29
redisStockAfter = 30
refreshed = true
```
