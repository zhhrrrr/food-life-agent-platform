# 开发日志-087-DDD分层边界验证脚本

## 本次目标

新增 DDD 分层边界验证脚本，并接入公司级 readiness。

## 新增脚本

```text
scripts/verify-ddd-boundaries.ps1
```

验证规则：

- domain 层不能 import infrastructure、trigger、app
- api 层只能作为接口契约，不能 import domain、infrastructure、trigger、app
- types 层保持轻量，不能 import 业务实现层
- infrastructure 层不能反向依赖 trigger、app
- domain 的 pom 不能依赖 infrastructure、trigger、app
- api 的 pom 不能依赖 domain、infrastructure、trigger、app

## 接入位置

```text
scripts/verify-company-readiness.ps1
```

执行顺序：

```text
use-java17-plus
  -> verify-microservice-boundaries
  -> verify-ddd-boundaries
  -> mvn test
  -> frontend build
```

## 价值

这一步不是新增业务接口，而是新增工程守门规则。

后续继续开发普通购买、拼团、秒杀、支付、评价、Agent 工具注册时，如果有人把基础设施实现倒灌进 domain，或者把 api 契约层写成业务实现层，脚本会直接失败。

## 验证

已执行：

```bash
powershell -ExecutionPolicy Bypass -File scripts/verify-ddd-boundaries.ps1
powershell -ExecutionPolicy Bypass -File scripts/verify-company-readiness.ps1 -SkipRuntimeSmoke
```

结果：

- DDD 分层边界验证通过
- 公司级 readiness 静态验证通过
