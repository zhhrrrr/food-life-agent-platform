# 开发日志 002：用户登录闭环第一版

## 一、本次开发目标

本次开发目标是在已有 `food-auth-starter` 和 `food-user-service` 骨架基础上，补齐第一版用户登录闭环。

目标链路：

```text
发送验证码
  -> 手机号验证码登录
  -> 自动创建用户
  -> 写入 Redis Token
  -> 携带 Token 调用 /api/user/me
  -> UserHolder 获取当前用户
  -> 登出删除 Token
```

当前阶段先使用 Redis 保存用户资料，目的是在没有 MySQL 表结构和数据库连接的情况下，先把登录主流程跑通。

后续接 MySQL 时，只需要替换 `IUserRepository` 的实现，不需要改 Controller 和领域接口。

### 6. 用户登录 Controller

文件：

```text
food-user-service/food-user-trigger/src/main/java/com/foodlife/user/trigger/http/UserAuthController.java
```

作用：

```text
提供用户登录相关 HTTP 接口。
```

当前实现接口：

```http
POST /api/user/code
POST /api/user/login
POST /api/user/logout
```

#### /api/user/code

功能：

```text
发送验证码。
```

实现逻辑：

```text
1. 校验手机号格式
2. 生成 6 位验证码
3. 写入 Redis
4. 设置 2 分钟过期时间
5. 日志打印验证码
```

当前没有接短信平台，验证码通过日志查看。

#### /api/user/login

功能：

```text
手机号验证码登录。
```

实现逻辑：

```text
1. 校验手机号格式
2. 从 Redis 获取验证码
3. 校验验证码是否一致
4. 根据手机号查询用户
5. 用户不存在则自动创建
6. 生成随机 Token
7. 将用户轻量信息写入 Redis Hash
8. 设置 Token 过期时间
9. 删除验证码
10. 返回 Token
```

Token 保存内容：

```text
id
nickName
icon
```

#### /api/user/logout

功能：

```text
退出登录。
```

实现逻辑：

```text
1. 从 authorization 请求头获取 Token
2. 删除 Redis 中的 food:login:token:{token}
3. 返回成功
```

## 三、当前登录流程

完整流程如下：

```text
1. 前端调用 POST /api/user/code?phone=手机号
2. user-service 生成验证码并写入 Redis
3. 前端调用 POST /api/user/login
4. user-service 校验验证码
5. user-service 查询或创建用户
6. user-service 生成 Token
7. user-service 将登录用户写入 Redis Hash
8. 前端保存 Token
9. 前端携带 authorization Token 调用 /api/user/me
10. food-auth-starter 解析 Token
11. RefreshTokenInterceptor 写入 UserHolder
12. UserController 从 UserHolder 获取当前用户
```

## 五、为什么这一步暂时没有接 MySQL

当前没有立即接 MySQL，是为了先让登录链路尽快可运行。

当前做法：

```text
用户资料暂时存在 Redis
```

后续演进：

```text
1. 新建 food_user_db
2. 新建 user 表
3. 新建 UserPO
4. 新建 UserMapper
5. 新建 MySqlUserRepository
6. 替换 RedisUserRepository
```

因为 Controller 和领域层都依赖 `IUserRepository`，所以替换仓储实现时不需要改登录接口。
