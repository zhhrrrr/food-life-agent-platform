# 开发日志 013：撤销统一下单流程模板

## 一、本次调整结论

本次在 `feature/remove-order-flow-template` 分支调整 trade-service 下单结构。

最终原则：

```text
设计模式用公共模板。
业务流程不强制抽象成统一模板。
```

也就是说：

```text
保留 xfg 迁移的 link/tree 设计模式模板。
撤销普通购买、拼团、秒杀共用的 OrderCreateTemplate 流程模板。
```

## 二、为什么撤销统一下单流程模板

普通购买、拼团、秒杀虽然都叫“下单”，但业务流程差异很大。

普通购买：

```text
套餐校验
按原价计算
创建订单
等待支付
```

拼团：

```text
活动校验
团状态校验
用户参团限制
团库存锁定
支付后成团或待成团
```

秒杀：

```text
秒杀时间窗口校验
Redis 库存扣减
用户限购
防重复下单
高并发削峰
可能异步落库
```

如果强行共用一个 `AbstractOrderCreateTemplate`，后续很容易出现：

```text
大量空钩子方法
大量 if tradeType 判断
子类覆盖大段流程
模板反而隐藏业务真实差异
```

所以本次撤销统一流程模板。

## 三、删除的业务流程模板

删除目录：

```text
food-trade-domain/src/main/java/com/foodlife/trade/domain/order/create
```

删除文件：

```text
OrderCreateTemplate.java
OrderCreateTemplateRouter.java
AbstractOrderCreateTemplate.java
NormalOrderCreateTemplate.java
```

这些文件属于“下单业务流程模板”，不是 xfg 公共设计模式模板。

## 四、保留的公共设计模式模板

公共模板仍然保留在：

```text
food-domain-patterns
```

核心模板：

```text
com.foodlife.patterns.framework.link.model1
com.foodlife.patterns.framework.link.model2
com.foodlife.patterns.framework.tree
```

这些是从 xfg 拼团项目 `xfg-wrench-starter-design-framework` 迁移出的设计模式模板。

## 五、普通购买现在怎么实现

普通购买业务流程现在回到：

```text
OrderDomainService.createNormalOrder
```

流程显式编排：

```text
1. 构建 OrderCreateContext
2. 执行 COMMAND 阶段 xfg 责任链校验
3. 调 business-service 获取套餐交易快照
4. 执行 SNAPSHOT 阶段 xfg 责任链校验
5. 调价格策略计算金额
6. 调 OrderFactory 创建订单主表
7. 保存订单主表
8. 调 OrderFactory 创建订单明细
9. 保存订单明细
10. 返回下单结果
```

## 六、当前仍然复用哪些能力

普通购买仍然复用：

```text
xfg link.model2 责任链模板
OrderPricingStrategy 价格策略
OrderFactory 订单工厂
OrderNoGenerator 订单号生成器
IOrderRepository 仓储接口
IBusinessPackagePort 外部服务端口
```

也就是说：

```text
共用能力，不共用流程。
```

## 七、后续拼团和秒杀怎么做

后续建议：

```text
NormalOrderService      普通购买流程
GroupBuyOrderService    拼团流程
SeckillOrderService     秒杀流程
```

三者可以复用：

```text
LinkArmory
BusinessLinkedList
ILogicHandler
StrategyHandler
OrderFactory
OrderNoGenerator
```

但不强制继承同一个下单流程模板。

## 九、本次结论

当前结构更贴近生产判断：

```text
设计模式公共化。
业务流程显式化。
不同业务只复用能力，不强行复用流程。
```
