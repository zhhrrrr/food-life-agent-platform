### 4. Maven 构建基线

文件：

- `pom.xml`

新增：

- `maven-enforcer-plugin`

约束：

- Java 版本必须 >= 17。
- Maven 版本必须 >= 3.8.1。

原因：

- 当前项目是 Spring Boot 3，必须使用 Java 17+。
- 本机默认 `mvn -v` 仍是 JDK 8，容易导致后续误操作。

本地 Maven 命令前应执行：

```powershell
.\scripts\use-java17-plus.ps1
```

### 5. 本地公司级验收入口

新增：

- `scripts/verify-company-readiness.ps1`

该脚本执行：

- 切换 Java 17+
- 微服务边界检查
- Maven 测试
- 前端构建
- 如果 Gateway 已启动，则继续执行基础设施检查、Nacos 配置检查、本地 smoke test

### 6. CI 统一质量门禁

文件：

- `.github/workflows/ci.yml`

处理内容：

- 原来 CI 分成 backend/frontend 两个 job，各跑各的命令。
- 现在调整为 `Project Readiness` job。
- CI 统一安装 Java 17 和 Node 22。
- 先执行 `npm ci`。
- 再执行：

```powershell
.\scripts\verify-company-readiness.ps1 -SkipRuntimeSmoke
```

这样本地与 CI 使用同一个验收入口，只是 CI 不启动 MySQL、Redis、Nacos、RabbitMQ、Seata、Sentinel 这些本地运行时组件。

## 当前判断

现在项目离“能接 Agent”最近的阻塞点不是微服务组件，而是：

- 接口契约
- 统一错误码
- 权限模型
- 写操作审计
- 真实支付边界

Agent 会把后端接口当工具调用。如果错误语义和权限边界不稳定，Agent 会放大这些问题。
