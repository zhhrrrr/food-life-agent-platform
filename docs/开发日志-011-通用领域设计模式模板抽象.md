# 开发日志 011：通用领域设计模式模板抽象

## 一、本次开发背景

上一版抽象的是：

```text
订单下单流程模板
```

但更准确的目标应该是：

```text
把责任链、策略、规则树、流程模板这些设计模式本身抽象成通用模板，
放在公共模块中，
让 trade、business、agent 等不同业务都可以调用。
```

因此本次新增根级公共模块：

```text
food-domain-patterns
```

它不属于某个具体业务服务，而是所有微服务领域层都可以复用的设计模式模板库。

模块：

```text
food-domain-patterns
```

```text
pom.xml
```

## 三、责任链模板

目录：

```text
food-domain-patterns/src/main/java/com/foodlife/patterns/chain
```

核心文件：

```text
BusinessChainHandler.java
BusinessChainRouter.java
```

### BusinessChainHandler

职责：

```text
定义一个通用责任链节点。
```

接口方法：

```text
group()
order()
support(context)
handle(context)
```

含义：

```text
group：链路分组，比如 trade.order.create.command.check
order：节点顺序
support：当前节点是否支持本次上下文
handle：节点处理逻辑
```

### BusinessChainRouter

职责：

```text
根据 group 找到对应责任链节点，
按 order 排序，
逐个执行。
```

这样不同业务只需要实现 Handler，不需要自己再写链路执行器。

## 四、策略模板

目录：

```text
food-domain-patterns/src/main/java/com/foodlife/patterns/strategy
```

核心文件：

```text
BusinessStrategy.java
BusinessStrategyRouter.java
```

### BusinessStrategy

职责：

```text
定义一个通用业务策略。
```

接口方法：

```text
group()
support(context)
apply(context)
```

含义：

```text
group：策略分组，比如 trade.order.pricing
support：当前策略是否支持本次上下文
apply：执行策略
```

### BusinessStrategyRouter

职责：

```text
根据 group 和 context 自动找到匹配策略并执行。
```

后续 trade-service 的普通购买、拼团、秒杀价格计算都会走这个模板。

## 五、规则树模板

目录：

```text
food-domain-patterns/src/main/java/com/foodlife/patterns/rule
```

核心文件：

```text
RuleNode.java
RuleTree.java
RuleTreeRouter.java
```

### RuleNode

职责：

```text
定义规则树中的一个规则节点。
```

方法：

```text
key()
apply(context)
next(context, result)
```

含义：

```text
key：节点唯一标识
apply：执行当前规则
next：根据上下文和当前结果决定下一个节点
```

### RuleTree

职责：

```text
定义一棵规则树。
```

方法：

```text
group()
root()
nodes()
```

### RuleTreeRouter

职责：

```text
根据 group 找到规则树，
从 root 节点开始执行，
直到 next 返回 null。
```

当前限制：

```text
最大执行深度 64
```

原因：

```text
防止规则树配置错误导致无限循环。
```

后续适用场景：

```text
优惠券规则
满减规则
会员价规则
Agent 工具权限规则
Agent 任务编排规则
秒杀资格判断规则
```

### 订单价格策略



### 订单流程模板

订单抽象模板：

```text

```

现在继承：

```text

```

订单模板本身仍保留业务流程细节，但流程模板能力来自公共模块。

## 八、为什么这样放

`food-domain-patterns` 放在根级，而不是放在 `food-trade-service` 里。

原因：

```text
1. 它不是 trade 独有能力
2. business-service 后续也可能用责任链和规则树
3. agent-service 后续一定会用规则树、策略和权限链
4. 根级模块可以被所有微服务按需依赖
```

## 九、后续业务怎么接入

### 接责任链

```text
1. 定义业务上下文
2. 定义业务 Handler 继承 BusinessChainHandler
3. 实现 group、order、handle
4. 调用 BusinessChainRouter.execute(group, context)
```

### 接策略

```text
1. 定义业务上下文和结果对象
2. 定义业务策略继承 BusinessStrategy
3. 实现 group、support、apply
4. 调用 BusinessStrategyRouter.apply(group, context)
```

### 接规则树

```text
1. 定义 RuleNode
2. 组装 RuleTree
3. 调用 RuleTreeRouter.execute(group, context)
```

### 接流程模板

```text
1. 继承 BusinessProcessTemplate
2. 实现 doProcess
3. 按需覆盖 beforeProcess、validate、afterProcess
```

## 十一、本次结论

本次完成的是“设计模式模板公共化”，不是单纯的订单流程重构。

当前已经沉淀出：

```text
通用责任链模板
通用策略模板
通用规则树模板
通用流程模板
```

trade-service 当前已经开始使用这些模板。

后续 business-service、agent-service 可以直接依赖 `food-domain-patterns`，不用再重复写一套责任链、策略路由和规则树执行器。
