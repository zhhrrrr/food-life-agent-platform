# 开发日志 072：微服务组件真实启用改造

## 一、改造目标

本次改造目标是让微服务组件默认真实生效，不再依赖 `false` 开关做演示式兜底。

核心原则：

- Nacos 默认启用，作为注册中心和配置中心。
- RabbitMQ 默认启用，消息生产、消费、健康检查都真实接入。
- Seata 默认启用，退款确认链路真实进入 AT 全局事务。
- Gateway 本地 IP/用户限流默认启用。
- Observability 普通请求日志默认启用。
- Boot 3 下不启用旧的 `feign.sentinel.enabled`，而是移除旧配置，保留 `spring.cloud.openfeign.circuitbreaker.enabled=true`。

## 二、默认启动路径改为 Nacos

修改文件：

```text
food-user-service/food-user-app/src/main/resources/application.yml
food-business-service/food-business-app/src/main/resources/application.yml
food-trade-service/food-trade-app/src/main/resources/application.yml
food-gateway-service/src/main/resources/application.yml
```

原来默认：

```yaml
spring:
  profiles:
    active: ${SPRING_PROFILES_ACTIVE:local}
```

现在默认：

```yaml
spring:
  profiles:
    active: ${SPRING_PROFILES_ACTIVE:nacos}
```

含义：

- 不传环境变量时，服务默认走 Nacos。
- Nacos 配置中心和注册中心是默认启动路径。
- 如果 Nacos 没有启动或配置没发布，服务应当启动失败，而不是静默退回本地假配置。

## 三、Nacos import 改为强依赖

原来：

```yaml
optional:nacos:food-common.yaml
```

现在：

```yaml
nacos:food-common.yaml
```

含义：

- Nacos 配置不存在时不再假装正常。
- 配置中心真正成为微服务运行前置依赖。

同时把：

```yaml
spring:
  cloud:
    nacos:
      config:
        import-check:
          enabled: true
```

明确打开。

## 四、公共 Nacos 配置真实启用

修改文件：

```text
deploy/nacos/configs/food-common.yaml
```

本次打开：

```yaml
management:
  health:
    rabbit:
      enabled: ${FOOD_RABBIT_HEALTH_ENABLED:true}

seata:
  enabled: ${SEATA_ENABLED:true}

food:
  mq:
    enabled: ${FOOD_MQ_ENABLED:true}
  observability:
    log-normal-request: ${FOOD_OBSERVABILITY_LOG_NORMAL_REQUEST:true}
```

含义：

- RabbitMQ 不可用时，健康检查能暴露真实问题。
- MQ 配置默认创建交换机、队列、绑定、监听器。
- Seata 默认代理数据源并接入全局事务。
- 普通请求日志默认打印，方便本地联调查看链路。

## 六、RabbitMQ 属性默认值启用

修改文件：

```text
food-business-service/food-business-infrastructure/src/main/java/com/foodlife/business/infrastructure/mq/BusinessRabbitMqProperties.java
food-trade-service/food-trade-infrastructure/src/main/java/com/foodlife/trade/infrastructure/mq/TradeRabbitMqProperties.java
```

原来：

```java

```

现在：

```java

```

含义：

- 配置缺失时，代码默认仍然启用 MQ。
- 不再出现“配置没配就关闭消息能力”的隐性兜底。

```text

```

- Gateway 原生用户维度限流生效。

## 九、启动脚本真实启用组件

修改文件：

```text
scripts/start-local-services.ps1
scripts/check-microservice-infra.ps1
```

默认 profile：

```powershell
[string]$SpringProfilesActive = "nacos"
```

脚本显式设置：

```powershell
$env:NACOS_DISCOVERY_ENABLED = "true"
$env:NACOS_CONFIG_ENABLED = "true"
$env:FOOD_RABBIT_HEALTH_ENABLED = "true"
$env:FOOD_MQ_ENABLED = "true"
$env:SEATA_ENABLED = "true"
$env:FOOD_OBSERVABILITY_LOG_NORMAL_REQUEST = "true"
```

含义：

- 脚本不会再偷偷关闭 Nacos。
- 脚本启动的服务会真实连接 RabbitMQ、Seata、Nacos、Sentinel、Prometheus 观测能力。
- 启动服务前会检查 MySQL、Redis、Nacos、RabbitMQ、Seata、Sentinel Dashboard 端口。
- 基础设施缺失时直接失败，避免用假运行掩盖问题。

## 十、为什么移除旧 Feign Sentinel 开关

本次没有把：

```yaml
feign:
  sentinel:
    enabled: false
```

简单改成 true，而是直接移除。

原因：

- 项目当前是 Spring Boot 3。
- 当前主链路已经使用 `spring.cloud.openfeign.circuitbreaker.enabled=true`。
- Feign 耗时观测使用 `spring.cloud.openfeign.micrometer.enabled=true`。
- 旧 `feign.sentinel.enabled` 属于老式 Sentinel Feign 接入方式，容易和 Boot 3 / OpenFeign Contract 组合产生兼容问题。

所以正确做法不是硬改 true，而是删除旧开关，保留当前更稳的 OpenFeign CircuitBreaker 接入方式。

## 十二、剩余 false 的说明

当前配置文件里可能仍能看到两类 `false`，它们不是微服务组件启停开关：

```text
JDBC useSSL=false
Grafana disableDeletion=false
```

说明：

- `useSSL=false` 是本地 MySQL 连接参数，表示本地数据库连接不使用 SSL，不代表关闭微服务组件。
- `disableDeletion=false` 是 Grafana provisioning 的看板删除策略，不代表关闭 Grafana。

## 十三、本次后的启动前置依赖
