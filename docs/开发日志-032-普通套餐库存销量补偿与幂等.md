# 开发日志 032：普通套餐库存销量补偿与幂等

## 一、开发目标

本次继续只做非 Agent 业务能力。

上一阶段已经跑通普通购买的库存和销量闭环，但普通订单状态在 `food_trade_db`，套餐库存和销量在 `food_business_db`，两个微服务之间没有分布式事务。

本次目标是补齐生产化骨架：

```text
trade-service 记录普通订单库存/销量同步本地消息
business-service 支持库存/销量变更幂等号 operationId
补偿任务扫描失败消息并重试
提供手动补偿接口
```

## 二、为什么要做这一步

普通订单的关键动作分成两类：

```text
创建订单前预占库存：
必须同步执行。没库存就不能创建订单。

订单状态改变后的库存/销量动作：
可以通过本地消息做最终一致性。
```

本次没有把普通购买全部改成异步，而是在订单状态已落库后，为跨服务库存/销量同步补可靠消息和重试能力。

## 四、数据变化

### 1. business-service 新增幂等表

```text
package_stock_change_record
```

核心字段：

```text
operation_id
package_id
quantity
change_type
change_status
```

`operation_id` 唯一，用于防止同一个库存/销量动作被重复执行。

### 2. trade-service 复用本地消息表

继续复用：

```text
trade_local_message
```

普通库存同步消息类型：

```text
NORMAL_PACKAGE_RELEASE_STOCK
NORMAL_PACKAGE_CONFIRM_SOLD
NORMAL_PACKAGE_ROLLBACK_SOLD
```

退款时会产生两条消息：

```text
NORMAL_PACKAGE_ROLLBACK_SOLD
NORMAL_PACKAGE_RELEASE_STOCK
```

原因是回滚销量和释放库存是两个远程动作，必须拆开记录，避免一个动作成功另一个失败后重试造成重复回滚。

## 五、业务流程

### 1. 普通订单取消

```text
1. trade-service 将订单状态 WAIT_PAY -> CANCELED
2. 写入 NORMAL_PACKAGE_RELEASE_STOCK 本地消息
3. 立即尝试调用 business-service 释放套餐库存
4. 成功则消息 SUCCESS
5. 失败则消息 INIT，等待补偿任务重试
```

### 2. 普通订单支付

```text
1. trade-service 将订单状态 WAIT_PAY -> PAID
2. 写入 NORMAL_PACKAGE_CONFIRM_SOLD 本地消息
3. 立即尝试调用 business-service 确认销量
4. business-service 根据 operationId 做幂等判断
```

### 3. 普通订单退款

```text
1. trade-service 将订单状态 PAID -> REFUNDED
2. 写入 NORMAL_PACKAGE_ROLLBACK_SOLD 本地消息并执行
3. 写入 NORMAL_PACKAGE_RELEASE_STOCK 本地消息并执行
4. 任一失败都可由补偿任务继续重试
```
