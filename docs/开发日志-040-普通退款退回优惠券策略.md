# 开发日志 040：普通退款退回优惠券策略

## 一、开发目标

本次继续补齐普通购买逆向流程。

上一阶段普通购买已经具备：

```text
下单占用套餐库存
支付确认销量
退款回滚销量并释放库存
下单使用优惠券
取消订单释放优惠券
优惠券过期扫描
```

但普通订单支付后退款时，还没有处理订单使用过的优惠券，会出现：

```text
订单已经 REFUNDED
库存销量已经回滚
用户券仍然 USED
```

本次目标是补齐：

```text
普通订单退款成功后退回优惠券
重复退款不重复退券
如果退款时优惠券已经过期，退回后状态为 EXPIRED
退款响应返回退券结果
```

## 二、业务规则

当前只处理普通购买订单。

规则：

```text
1. 只有 PAID 状态订单可以退款
2. 普通退款成功后，订单状态 PAID -> REFUNDED
3. 普通退款成功后，发送销量回滚和库存释放消息
4. 如果订单使用了优惠券，则释放该用户券
5. 释放时必须匹配 userCouponId、userId、orderId、USED 状态
6. 如果用户券仍在有效期内，退回为 UNUSED
7. 如果用户券已经过期，退回为 EXPIRED
8. 重复退款直接返回 repeat，不重复释放优惠券
```

拼团退款暂不处理优惠券，因为当前优惠券只接入普通购买。

```text

released
couponStatus
```

用于表达释放动作有没有发生，以及释放后的目标状态。

### 2. 优惠券释放策略

`CouponService` 增加：

```text
releaseCouponWithResult(userCouponId, userId, orderId)
```

释放状态判断：

```text
validEndTime < now -> EXPIRED
否则 -> UNUSED
```

仓储释放时显式传入目标状态：

```text
releaseUsedCoupon(userCouponId, userId, orderId, couponStatus)
```

## 六、当前结论

普通购买优惠券正向和逆向流程进一步闭环：

```text
下单：UNUSED -> USED
未支付取消：USED -> UNUSED 或 EXPIRED
支付后退款：USED -> UNUSED 或 EXPIRED
重复退款：不重复退券
```
